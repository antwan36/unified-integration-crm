# Unified Integration CRM — project status

Read this first if you're picking up work on this project in a new Claude Code session (e.g. on a different Mac). It's a native Electron CRM built for Unified Integration (Lancaster PA smart-home/AV installer), covering leads, email, invoicing, estimates, and scheduling in one place.

**This file changes fast and has fallen out of date before — don't trust it blindly.** Grep the actual source (`src/main/ipc/handlers.ts` for the full IPC surface, `src/shared/types.ts` for data shapes) before assuming a feature is or isn't built. This project has also been observed changing *while* a session is actively reading it (concurrent edits from elsewhere) — if something you read doesn't match what you expected, re-read rather than assume you mis-saw it.

## Architecture
- Electron + React + TypeScript, Vite build (`electron-vite`). Renderer in `src/renderer/src`, main process in `src/main`, shared types in `src/shared/types.ts`.
- **Data storage**: shared **Neon Postgres** database. `src/main/db/` holds the `pg`-based data-access layer. Schema lives in `src/main/db/schema.ts`, applied idempotently on every connect via `ensureSchema()`.
- **Per-machine setup**: each Mac "Connects its workspace" on first launch — paste the same Neon connection string + workspace passphrase used on every other machine (`src/renderer/src/pages/ConnectWorkspace.tsx`, `src/main/secrets/workspace.ts`). The passphrase derives an AES key (fixed salt, `scrypt`) used to encrypt IMAP/Square credentials before they're stored in the shared `settings` table.
- **Auth**: local login gate (`src/main/db/users.ts`), bcrypt-hashed, shared across machines via the same Postgres `users` table. Team accounts: `auth:createUser` lets an already-logged-in user add a teammate (Settings → Team).
- **Email (IMAP + SMTP)**: `src/main/imap/sync.ts` polls INBOX every 10 min (`src/main/backgroundSync.ts`) and on launch, parses Formspree lead-notification emails into new Contacts, links other mail to existing contacts by sender, creates "unmatched" contacts for unknown senders. `src/main/email/smtp.ts` sends via `nodemailer` — compose/reply UI in `ContactDetail.tsx`.
- **Invoicing (Square)**: `src/main/square/invoices.ts`. Invoices can be sent immediately or saved as a **draft** (`CreateInvoiceInput.draft`) and sent later (`sendDraftInvoice`). Drafts can be deleted; published invoices can be canceled (`deleteOrCancelInvoice`) unless already paid/refunded/canceled/failed. Partial payments and refunds are tracked (`Invoice.paidCents`/`refundedCents`, computed via `sumInvoicePaidCents`/`sumOrderRefundCents` in `square/client.ts`) and refreshed on the same 10-min background sync and on manual refresh.
- **Estimates**: fully custom e-signature flow (Square has no public Estimates API — confirmed via Square's own developer forum). `estimate-portal/` is a separate Vercel project (own repo/folder, not part of this Electron app's build) that serves the signing page (`/e/:token`) and reads/writes directly to the same Neon Postgres via `DATABASE_URL`. Draft estimates can be duplicated into a new draft (`onDuplicate` in `EstimateDetail.tsx`) and lines can be copied into a new invoice too (`CopyFromState`, shared between `NewInvoice.tsx`/`NewEstimate.tsx`).
- **Catalog**: `catalog_items` table — reusable priced line items (name/description/price) pickable from a dropdown (`LineItemsGrid.tsx`, shared by NewInvoice/NewEstimate/EstimateDetail) when building an invoice or estimate. Managed at `/catalog`.
- **Product-link scraping**: paste or drop a product URL into a line item's Link column and `src/main/catalog/scrape.ts` (uses `cheerio`) fetches the page, reads JSON-LD `Product`/`ProductGroup` schema (falling back to OG/meta tags, then a regex `$` price scan) and auto-fills the description/price for that row. Handles bot-blocked sites (403/429/Cloudflare) with a clear error instead of a silent failure.
- **Calendar feed**: `src/main/calendar/feed.ts` generates a `webcal://` link (`Settings` → "Job calendar") pointing at `estimate-portal`'s `/cal/:token.ics` endpoint (`estimate-portal/api/cal/[token].js`), which reads scheduled `tasks` (the ones with `startAt` set) straight from Postgres and serves an RFC 5545 `.ics` feed — subscribe once from Calendar.app/phone and new scheduled jobs show up automatically. The feed URL only appears once the estimate signing page URL (Settings) is saved, since they're served from the same Vercel deployment. **Currently broken in production — see "Known issues" below.**
- **Global search**: Cmd+K opens `SearchPalette.tsx`, a fuzzy-ish substring search across contacts/invoices/estimates loaded client-side.
- **Email section**: `/email` (`src/renderer/src/pages/Email.tsx`) is a unified inbox across all contacts — every `activities` row of `type = 'email'`, joined to its contact, newest first. Backed by `email:list`/`email:unreadCount`/`email:markRead` IPC (`src/main/db/activities.ts`: `listEmailActivities`/`countUnreadEmails`/`markActivityRead`). Read/unread is a plain `read BOOLEAN` column on `activities` (default `TRUE`; IMAP sync explicitly sets `read: false` on newly-synced inbound mail — see `src/main/imap/sync.ts`). Composing to an address with no existing contact auto-creates one via `contacts:findOrCreateByEmail` (`findOrCreateContactByEmail` in `src/main/db/contacts.ts`), marked `unmatched: true` same as unrecognized inbound senders. Sidebar shows an unread-count badge next to "Email" (polled every 60s in `Layout.tsx`).
- **Multiple email accounts**: the app supports any number of IMAP/SMTP accounts (e.g. two company mailboxes), not just one. Managed in Settings (`src/renderer/src/pages/Settings.tsx`, "Email accounts" section) via `emailAccounts:list/create/update/delete/test` IPC, backed by the `email_accounts` table (`src/main/db/emailAccounts.ts` — passwords encrypted per-row with the same workspace-derived key as everything else). `runImapSyncAll()` in `src/main/imap/sync.ts` polls every configured account's INBOX independently (each with its own `sync_state` row, keyed by the account's id) and aggregates results; `backgroundSync.ts` and the "Sync now" button both call it. Every synced/sent email activity carries `emailAccountId` (nullable `TEXT` column on `activities`, no FK) so the Email inbox and each contact's compose/reply UI can show/pick which account a message came from or send through — replying defaults to the account a message arrived on; new compose defaults to the first configured account with a picker if there's more than one. **One-time upgrade path**: this replaced an earlier single-account design (`imap_credentials` under one encrypted `settings` row); `migrateLegacyImapAccountIfNeeded()` runs once at startup/workspace-connect to copy that old account (and its IMAP sync progress) into `email_accounts` if the table is still empty — but as of 2026-07-22 that legacy key was actually never populated on the production workspace (Settings never showed a "Connected" banner for it), so there was nothing to migrate; both real company mailboxes still need to be added fresh via Settings.
- **Revenue chart**: `InvoiceRevenueChart.tsx` on the Invoices page, a small inline SVG bar chart (`InvoiceMonthlyPoint[]` from the invoices IPC).
- **Packaging**: `npm run dist:mac` (via `electron-builder`) → `.dmg` (both arm64 and x64) in `crm/dist/`. Unsigned (no Apple Developer cert) — first launch on a new Mac needs `xattr -cr` or right-click-Open once. On this iCloud-synced repo, `electron-builder`'s lockfile can occasionally throw "Unable to update lock within the stale threshold" if a build races another process (e.g. iCloud sync, or another session building concurrently) — just retry.

## Known gotchas hit during development (don't redo this work)
- `better-sqlite3` and node-gyp **do not work** in this repo's path — the project directory has spaces in it (`Unified Integration`), which breaks native module compilation. The DB layer uses `pg` (pure JS) for this reason.
- Square's Create Invoice API requires `accepted_payment_methods` AND `delivery_method` in the request body even for a draft — both are set unconditionally in `createSquareInvoice()`.
- **Stale running processes**: if you rebuild and reinstall while an old instance is still running, macOS will just refocus the old process. Always fully quit (`pkill -f "Unified Integration CRM"`, confirm with `ps aux`) before relaunching after a reinstall.
- **Dev/packaged storage collision (fixed)**: dev (`npx electron .`) and packaged builds used to share the same `userData` folder, wiping the real app's workspace connection during dev testing. Fixed in `src/main/index.ts` via a separate `unified-integration-crm-dev` folder for unpackaged runs.
- **Settings text inputs with a placeholder that looks like real data**: several Settings fields use the actual production value as their `placeholder` (e.g. the estimate signing page input's placeholder literally is `https://unified-integration-estimates.vercel.app`). Gray placeholder text is easy to mistake for a saved value when spot-checking via screenshot — always confirm via the green "Connected: …" banner (or a console `window.api.settings.get…()` call), not the input's displayed text.
- **Computer-use click timing on this app**: clicks immediately after a page transition or on freshly-rendered buttons have occasionally not registered (Save buttons, nav links) — if a screenshot shows no state change after a click, retry the exact same click once before concluding something is broken.
- **Intermittent `AggregateError` from `pg`**: occasional IPC-triggered Postgres queries throw `AggregateError` (Neon connection blip) — most common right after a fresh launch (e.g. an empty/broken Cmd+K search on the very first open), but has also been observed later in a session on a single action (e.g. deleting an invoice failed twice in a row with `AggregateError` before succeeding on the third click). Retrying the same action resolves it. Not treated as a code bug — no fix attempted, since it's Neon-side connection churn, not application logic.

## Feature set
Leads/email ingestion (IMAP+Formspree) across any number of configured email accounts, SMTP send/reply (per-account "from" selection), a unified Email inbox across all contacts with read/unread tracking and compose-to-any-address, Square invoicing (send-now or save-as-draft, cancel/delete, partial payment + refund tracking), custom-built e-signature Estimates (external Vercel portal, currently down — see Known issues), Tasks with optional scheduling (`startAt`/`endAt`/`location`, feeds the calendar subscription), stale-lead follow-up panel, per-contact lifetime revenue + an invoices-page revenue chart, file attachments (stored as Postgres `bytea`, 10MB cap), contact job type + filter, desktop notifications (new lead / invoice paid), CSV export (contacts/invoices), team accounts, a reusable priced Catalog with product-link auto-scraping into line items, a global Cmd+K search palette, and a subscribable calendar feed for scheduled jobs.
